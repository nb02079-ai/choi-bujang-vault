# 완성본 시연 순서와 정리 (DEMO_AND_SUMMARY)

작성일은 2026-10-27이고 대상은 보안 Agent **Endministrator**의 「이 PC 상태 관제」입니다. 코드 기준 커밋은 `f358fa3a7d2f9b324120779a274cb165624a0110`(브랜치 `host-status`)이며, 이 문서와 스크린샷은 그 뒤에 문서 커밋으로 들어갑니다. 코드는 바뀌지 않았습니다.

## 0. 읽는 법

이 문서에서 값과 확인은 아래 낱말로만 구분합니다.

| 표시 | 뜻 |
|---|---|
| **실측** | 이 PC에서 방금 읽은 값(작성자가 직접 실행한 결과) |
| **예시 값** | 실제 조회 결과가 아닌 설명용 값. **이 앱은 PC 값에 예시 값을 쓰지 않습니다.** 예제 모드(`-Demo`)에서도 SDP 줄만 예제입니다. |
| **시험용 입력** | 시험을 위해 일부러 만든 가짜 읽기 결과. 이것으로 만든 화면은 실제 실패가 아닙니다. |
| **확인 불가** | 앱이 읽지 못해 값을 보이지 않는 항목(화면에 나오는 상태) |
| **사용자 시연 확인(보고)** | 사용자가 시연 순서를 브라우저에서 직접 따라 해 보고 「확인 끝」이라고 **보고**한 것. **항목별 결과(되는 것, 아쉬운 것)와 화면 문구는 받지 못했습니다.** 작성자가 직접 확인한 것이 아닙니다. |
| **미확인** | 확인하지 못한 것. 된다고 쓰지 않습니다. |

## 1. 한 줄 요약

PC의 CPU, 메모리, 디스크, 방화벽을 **이 PC에서 실제로 읽어** 맨 위 카드 4개로 보이고, 아래에 추이와 기록(네트워크, 방화벽, Windows 기록 경고·오류 건수)을 보이는 앱입니다. 읽지 못한 항목은 값 없이 「확인 불가」, 이유, 다음에 할 일을 보이며, 설치 프로그램(포장)은 **보류** 상태입니다.

## 3. 핵심 기능 3가지와 시연 순서

핵심 기능: **① 실측 상태 카드 4개 ② 추이와 기록 ③ 「다시 조회」, 대기, 실패 화면, 실측/예시 구분**

준비: `on-client` 폴더, Node.js 22~24(확인한 것은 24.21.0). 시연 중에 공격이나 침투를 흉내 내는 동작은 하지 않습니다.

| 순서 | 할 일 | 화면에서 보일 것 | 근거 상태 |
|---|---|---|---|

| 7 | 실측/예시 구분: `-Port 5190 -Demo`로 다른 창에서 실행 | SDP 줄만 「예제 자료 (SDP 아님)」, CPU·메모리 카드는 그대로 「실측」 배지 | API 응답은 작성자가 확인. 화면은 사용자 시연 확인(보고, 항목별 결과 미수령) |

시연 중 알아 둘 점
- 이 PC에서는 모든 항목을 읽을 수 있어서 **실제로 「확인 불가」 카드를 만들어 보일 수 없습니다.** 「확인 불가」 화면은 시험용 입력으로 만든 스크린샷(5.1)으로만 보입니다. 이 PC에서 확인 불가를 만들기 위해 권한이나 설정을 바꾸지 않습니다.
- 실측 값은 시연하는 PC와 시각의 값입니다. 스크린샷의 숫자를 현재 값처럼 말하지 않습니다.
- 브라우저를 같이 열고 있으면 CPU 값이 평소보다 높게 나올 수 있습니다(실제로 높았던 값).

## 4. 아직 안 되거나 「확인 불가」로 남은 한계

| 구분 | 한계 | 상태 |
|---|---|---|
| 포장 | `package-app`, 승인 실행 환경, 운영 앱 승인 키가 없어 **포장을 보류**. Inno Setup(`ISCC.exe`)도 미설치. 설치 프로그램(setup.exe)은 **없음** | 보류. `docs/PACKAGING_PENDING.md` |
| 연결 | 실제 SDP, AI 연결과 설명, 보안 조치 집행, 실제 OSV 조회: **연결 없음**(연결 설정이 필요) | 지원하지 않음 |
| 권한 | Security 기록은 관리자 권한이 필요해 **읽지 않음**. 권한이 필요한 항목은 권한을 올리지 않고 「확인 불가」 | 설계된 동작 |
| 범위 | 방화벽 규칙은 개수만 읽음. IP·MAC 주소는 읽지도 표시하지도 않음. Windows 기록은 최근 24시간, 한 종류당 10,000건까지 | 설계된 한계 |
| 추이 | 앱이 켜진 동안의 메모리 값만 있고 끄면 사라짐. CPU는 250ms 평균 | 설계된 한계 |
| 환경 | Windows 11 Pro, Node.js 24.21.0, Windows PowerShell 5.1, Edge에서만 확인. **다른 PC, 다른 Windows, Node 22·23, 다른 브라우저는 미확인** | 미확인 |
| 사용자 확인 | 3번 표의 「사용자 시연 확인」 항목(「다시 조회」 클릭, Tab 조작, 서버 종료 뒤 실패 화면, 예제 모드 화면, 탭 전환). 사용자가 확인 끝났다고 보고했으나 **항목별 결과와 화면 문구는 받지 못해** 작성자는 된다고 단정하지 않음 | 보고만 있음 |
| 화면 | 제공 「다시 불러오기」와 관제 「다시 조회」는 서로 연결되어 있지 않음(버튼 2개). 추이 줄에 `TREND_…` 같은 코드 문구가 그대로 보임 | 알려진 불편 |
| 단계 | 13~20단계 확인은 연결 없음과 예제 자료 범위. 21·22단계 공식 접수 연결과 v1.0 표시는 없음. 22단계 통과는 원문 검토 기준의 수료 | `STUDENT_RELEASE_CHECK.md` |
| 사용자 시각 | 사용자가 화면과 시연을 확인한 정확한 시각은 기록하지 않음(작성일 2026-10-27, 시연 확인 보고는 스크린샷 작성 17:11 이후) | 기록 없음 |

## 6. 같은 결과를 다시 만드는 명령과 확인 순서

3. 브라우저로 `http://127.0.0.1:5189/` → 3번 표의 순서 2~8을 차례로 확인
