# 학생 데이터 보존 계획 (STUDENT_DATA_PLAN)

이 문서는 22단계에서 학생이 새로 작성했습니다. 작성일은 2026-10-27입니다. 보존·백업·복원 절차와 그 제한을 적습니다. 실제로 실행해 본 것과 실행하지 않은 것을 나눴습니다. 키, 토큰, 비밀번호는 이 문서에 없습니다.

## 1. 보존 대상

### 1.1 Git 저장소 안에 있는 것

| 대상 | 위치 | 비고 |
|---|---|---|
| 학생 구현 코드 | `on-client/student/extension.mjs` | 13~20단계 화면 8개. 서버나 브라우저 저장소에 데이터를 쓰지 않음(코드 확인: `localStorage`, `sessionStorage`, `fetch`, 파일 쓰기 호출이 없음) |
| 학생 문서 | `on-client/docs/STUDENT_RUNBOOK.md`, `STUDENT_RELEASE_CHECK.md`, `STUDENT_DATA_PLAN.md` | 21·22단계에서 작성 |
| 제공 코드와 문서 | `on-client/`의 나머지 | 제공 파일(`public/index.html`의 표시 이름 변경 하나가 예외). 학생 데이터가 아닙니다. |
| 단계별 이력 | 원격 브랜치 `on-13`~`on-21` (9개) | 확인함. `on-22`는 push한 뒤 같은 방식으로 남음 |

### 1.2 Git 밖에 있는 것

방어전 저장소의 `.gitignore`는 아래를 Git에서 제외합니다. 이 파일들은 `git clone`으로 복원되지 않습니다.

| 대상 | 성격 |
|---|---|
| `.env`, `.env.*` | 비밀 설정 값. 저장소에 들어간 것은 비밀 없는 견본 `on-client/.env.example`뿐입니다. |
| `supabase/` | 데이터베이스 스크립트(운영자 몫 포함) |
| `policy/test-policy.json`, `policy/audit.log` | 시험 정책과 감사 이력 |
| `xdr/alerts.log` | 경보 기록 |
| `artifacts/`, `bundle-notes.json`, `public/aleph.json` | 산출물과 배포 신원 |

`on-client`가 직접 저장하는 데이터는 조치 기록용 SQLite 파일(`src/actions/store.mjs`)뿐이며, 이 파일은 운영자가 `databasePath`로 지정한 기존 파일입니다. 이 PC에는 조치 연결 설정이 없어 만들어지지 않았습니다.

## 2. 백업

| 단계 | 방법 | 실행 여부 |
|---|---|---|
| 코드와 문서 | 단계별 브랜치를 `git push origin <브랜치>`로 원격에 올림 | 실행함. `on-13`~`on-21`이 원격에 있음(`git ls-remote --heads origin`으로 9개 확인) |
| 로컬 보조 백업 | 큰 변경 전에 `git branch backup-...`로 브랜치를 남김 | 실행함. `backup-before-scrub2`, `backup-step6`이 로컬에 있음 |
| 원본 폴더 보존 | 새 환경 확인은 `git clone`으로 별도 폴더에 함. 원래 폴더는 건드리지 않음 | 실행함(22단계) |
| `.env` 등 Git 밖의 파일 | 소유자가 저장소 밖의 안전한 위치에 직접 복사해 보관. 키 값은 문서, 커밋, 캡처에 넣지 않음 | 실행하지 않음. 절차만 적었습니다. |
| 조치 SQLite 파일 | 운영자가 보관 | 이 PC에 없어 해당 없음 |

## 3. 복원

1. 코드와 문서: 빈 폴더에서 `git clone -b <브랜치> https://github.com/nb02079-ai/choi-bujang-vault.git`로 내려받고 `git rev-parse HEAD`로 40자리 커밋을 확인합니다. 22단계에서 `on-21`로 실행했고 HEAD가 기록한 커밋과 같았습니다.
2. 줄바꿈: Windows에서 `core.autocrlf=true`이면 파일 줄바꿈이 바뀌어 해시를 원문 그대로 계산하면 제공 원본과 다르게 나옵니다. 내용 비교는 줄바꿈을 감안해야 합니다(`STUDENT_RUNBOOK.md` 6.1절).
3. `.env`와 연결 설정: Git에서 복원되지 않습니다. 학생이 보관한 사본이 있으면 거기서 복원하고, 없으면 담당자에게 재발급을 요청합니다. 설정 파일(native 호스트, SDP)은 담당자가 발급하며 직접 만들거나 다른 사람의 파일을 복사하지 않습니다.
4. 조치 기록과 정책의 복원: 이 PC에서 실행하지 않았습니다. 기록상 방어전 앱에는 정책 사본 비교(`npm run policy:diff`)와 정책 복원(`npm run policy:restore`)이 있으나, 이번 22단계에서는 실행하지 않았으므로 복원 가능하다고 주장하지 않습니다.
5. 복원 뒤 확인: `STUDENT_RUNBOOK.md` 4절 절차로 `npm run check`와 시작을 실행하고, `STUDENT_RELEASE_CHECK.md`의 표와 비교합니다.

## 4. 제한

- 원격 저장소(GitHub)가 삭제되거나 접근이 막히면 로컬 폴더가 유일한 사본이 될 수 있습니다. 이 PC 밖의 추가 백업(예: 다른 위치의 `git clone`)은 22단계에서 새 폴더 하나만 만들었습니다.
- 10-13에 이력을 두 번 다시 써서 2~5단계와 보너스 커밋 번호가 이전 판과 다릅니다. 옛 번호로 복원을 시도하면 맞지 않을 수 있습니다.
- 옛 공개 커밋과 태그에 가상 메모가 남아 있어 2단계의 과거 노출은 해소되지 않았습니다. 이력에는 옛 `sk-` 모양 가짜 값도 남아 있습니다. 이 둘은 이 단계에서 고치지 않았습니다.
- Git 밖의 파일은 자동 백업이 없습니다. 보관을 소유자가 직접 해야 하며 이 문서는 그 보관이 되어 있다고 주장하지 않습니다.
- 이 계획은 실행해 본 범위(코드·문서 clone, 브랜치 push)를 넘어 복원 성공을 보장하지 않습니다.
